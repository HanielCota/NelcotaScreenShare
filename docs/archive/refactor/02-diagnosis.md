# 02 — Diagnosis

## An honest reading before the list

The project is **not messy across the board**. The server has above-average discipline for its size: `strict` with `noUncheckedIndexedAccess`, **zero `any`**, Zod at every boundary, `server-only` throughout the DAL, type-aware oxlint with `import/no-cycle` and layers via `no-restricted-imports`, no circular imports, 2.24% duplication and integration tests against real Postgres.

The "verbose and tangled" feeling comes from **four concentrated hot spots**:

1. **God components and hooks on the client**: the mascot, the pre-join screen and the room, plus the `/api/token` handler.
2. **Organization that changed criteria halfway through**: `features/` only for the admin, `components/` depending on `app/`, three auth folders and `lib/` used as a junk drawer.
3. **Duplication concentrated in the panel**: tables, filters, exports and auth forms.
4. **Guardrails that exist but protect nothing**: lint is red, there is no remote and no CI running, there is no E2E and no client test at all.

That is why the proposal (doc 03) is **surgical** and not a Clean Architecture rewrite.

Severity: **high** = causes a bug or blocks evolution today; **medium** = recurring cost on every change; **low** = noise. Effort: **S** < 2 h, **M** 2–8 h, **L** > 8 h.
